# Med Spa Accounting Automation - Desktop Application

**Date:** 2025-11-20
**Updated:** 2025-11-20 (Finalized Architecture)
**Goal:** Build an Electron Desktop Application to automate Med Spa accounting workflows

---

## Executive Summary

Build a local desktop application that allows you to:
1. **Upload EMR transaction files** → Parse and stage transactions
2. **Automatically match customers** → Via crosswalk with fuzzy matching for edge cases
3. **Map EMR services to QuickBooks items** → With exception handling for unmapped services
4. **Upload Credit Card statements** → Categorize and map business expenses
5. **Generate Transaction Pro-ready CSVs** → For import into QuickBooks Desktop

**Architecture Decision:** Electron Desktop App (not cloud-based PWA)
- **Why:** HIPAA compliance simplified, zero hosting costs, complete data privacy
- **Benefits:** Local SQLite database, offline operation, full audit trail via SQL queries

## Architecture Overview

**Desktop Application:**

- **React 18 + TypeScript** - Modern UI framework
- **Tailwind CSS** - Styling and design system

- **Node.js** (built into Electron) - Runtime environment

**Deployment:**
- **Build:** electron-builder for Windows/Mac/Linux installers
- **Auto-update:** electron-updater for automatic updates
- **Cost:** $0/month (no hosting, runs locally)

## Database Schema (SQLite)

### Core Tables

#### 1. `customers` (The Crosswalk)
```sql
CREATE TABLE customers (
    id                 TEXT PRIMARY KEY,           -- UUID generated by app
    cid                TEXT UNIQUE NOT NULL,       -- Format: CID-{uuid}
    customer_name_emr  TEXT,
    emr_id             TEXT,
    customer_name_qb   TEXT,
    qb_list_id         TEXT,
    is_active          INTEGER DEFAULT 1,          -- SQLite boolean: 1=true, 0=false
    created_at         TEXT DEFAULT (datetime('now')),
    updated_at         TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_customers_cid ON customers(cid);
CREATE INDEX idx_customers_emr_id ON customers(emr_id);
```

#### 2. `customer_history` (Version Tracking)
```sql
CREATE TABLE customer_history (
    id                 TEXT PRIMARY KEY,
    customer_id        TEXT REFERENCES customers(id),
    cid                TEXT,
    customer_name_emr  TEXT,
    emr_id             TEXT,
    customer_name_qb   TEXT,
    qb_list_id         TEXT,
    change_type        TEXT,                       -- created, updated, merged
    changed_at         TEXT DEFAULT (datetime('now')),
    changed_by         TEXT DEFAULT 'primary_user',
    snapshot           TEXT                        -- JSON string of full row data
);

CREATE INDEX idx_customer_history_customer_id ON customer_history(customer_id);
CREATE INDEX idx_customer_history_changed_at ON customer_history(changed_at);
```

#### 3. `service_mappings` (EMR → QB Items)
```sql
CREATE TABLE service_mappings (
    id                 TEXT PRIMARY KEY,
    emr_service_name   TEXT NOT NULL UNIQUE,
    qb_item_name       TEXT NOT NULL,
    qb_item_hierarchy  TEXT,                       -- e.g., "Injectables:Dysport per Unit"
    asset_account      TEXT,                       -- Inventory account if applicable
    income_account     TEXT NOT NULL,
    tax_code           TEXT,                       -- Tax, Non
    is_active          INTEGER DEFAULT 1,
    created_at         TEXT DEFAULT (datetime('now')),
    updated_at         TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_service_mappings_emr_service ON service_mappings(emr_service_name);
CREATE INDEX idx_service_mappings_active ON service_mappings(is_active);
```

#### 4. `payment_type_mappings`
```sql
CREATE TABLE payment_type_mappings (
    id                 TEXT PRIMARY KEY,
    payment_type       TEXT UNIQUE NOT NULL,       -- Visa, Mastercard, Alle Rewards, etc.
    category           TEXT NOT NULL,              -- customer_paid, vendor_receivable
    clearing_account   TEXT NOT NULL,              -- 1030 · Merchant Clearing, etc.
    is_active          INTEGER DEFAULT 1,
    created_at         TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_payment_type ON payment_type_mappings(payment_type);
```

#### 5. `file_uploads` (Audit Trail)
```sql
CREATE TABLE file_uploads (
    id                 TEXT PRIMARY KEY,
    filename           TEXT NOT NULL,
    file_type          TEXT NOT NULL,              -- emr, cc_statement
    row_count          INTEGER,
    uploaded_at        TEXT DEFAULT (datetime('now')),
    processed_at       TEXT,
    status             TEXT,                       -- uploaded, matched, exported
    user_id            TEXT DEFAULT 'primary_user'
);

CREATE INDEX idx_file_uploads_type ON file_uploads(file_type);
CREATE INDEX idx_file_uploads_uploaded_at ON file_uploads(uploaded_at);
```

#### 6. `transactions_staging` (Pre-Export Buffer)
```sql
CREATE TABLE transactions_staging (
    id                 TEXT PRIMARY KEY,
    upload_id          TEXT REFERENCES file_uploads(id),
    customer_cid       TEXT,
    invoice_number     TEXT,
    transaction_date   TEXT,                       -- ISO 8601 date format
    service_name       TEXT,
    quantity           REAL,
    price              REAL,
    amount             REAL,
    payment_type       TEXT,
    transaction_data   TEXT,                       -- JSON string of original row
    mapped_data        TEXT,                       -- JSON string after mapping applied
    created_at         TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_transactions_staging_upload_id ON transactions_staging(upload_id);
CREATE INDEX idx_transactions_staging_customer_cid ON transactions_staging(customer_cid);
CREATE INDEX idx_transactions_staging_date ON transactions_staging(transaction_date);
```

#### 7. `expense_categories` (CC Expense Mapping)
```sql
CREATE TABLE expense_categories (
    id                 TEXT PRIMARY KEY,
    merchant_pattern   TEXT NOT NULL,              -- "ALLERGAN%", "ZO SKIN%", etc.
    category_name      TEXT NOT NULL,              -- "COGS - Injectables"
    expense_account    TEXT NOT NULL,              -- "5100 · COGS:Injectables"
    is_cogs            INTEGER DEFAULT 0,          -- 1 for inventory purchases
    is_active          INTEGER DEFAULT 1,
    created_at         TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_expense_categories_pattern ON expense_categories(merchant_pattern);
CREATE INDEX idx_expense_categories_active ON expense_categories(is_active);
```

#### 8. `expense_transactions` (Uploaded CC Transactions)
```sql
CREATE TABLE expense_transactions (
    id                 TEXT PRIMARY KEY,
    upload_id          TEXT REFERENCES file_uploads(id),
    transaction_date   TEXT,                       -- From CC statement
    posted_date        TEXT,                       -- When it posted
    card_last_four     TEXT,                       -- e.g., "3323"
    merchant           TEXT,
    capital_one_category TEXT,                     -- Their pre-categorization
    amount             REAL,
    category_id        TEXT REFERENCES expense_categories(id),
    expense_account    TEXT,                       -- Final GL account
    memo               TEXT,
    status             TEXT,                       -- pending, categorized, exported
    transaction_data   TEXT,                       -- JSON of original row
    created_at         TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_expense_transactions_upload_id ON expense_transactions(upload_id);
CREATE INDEX idx_expense_transactions_date ON expense_transactions(transaction_date);
CREATE INDEX idx_expense_transactions_merchant ON expense_transactions(merchant);
CREATE INDEX idx_expense_transactions_status ON expense_transactions(status);
```

#### 9. `audit_log` (Complete Audit Trail)
```sql
CREATE TABLE audit_log (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp          TEXT DEFAULT (datetime('now')),
    action             TEXT NOT NULL,              -- 'file_uploaded', 'customer_created', etc.
    entity_type        TEXT,                       -- 'customer', 'service_mapping', 'transaction'
    entity_id          TEXT,                       -- CID, mapping ID, etc.
    details            TEXT,                       -- JSON with full context
    user_id            TEXT DEFAULT 'primary_user'
);

CREATE INDEX idx_audit_log_timestamp ON audit_log(timestamp);
CREATE INDEX idx_audit_log_action ON audit_log(action);
CREATE INDEX idx_audit_log_entity ON audit_log(entity_type, entity_id);
```

### Sample Audit Queries

```sql
-- What happened in the last 30 days?
SELECT * FROM audit_log
WHERE timestamp >= date('now', '-30 days')
ORDER BY timestamp DESC;

-- Who accessed a specific customer?
SELECT * FROM audit_log
WHERE entity_type = 'customer'
  AND entity_id = 'CID-a3f9b2c1'
ORDER BY timestamp DESC;

-- All exports generated this month
SELECT * FROM audit_log
WHERE action = 'export_generated'
  AND timestamp >= date('now', 'start of month');

-- Full compliance report (90 days)
SELECT
    date(timestamp) as day,
    action,
    COUNT(*) as count
FROM audit_log
WHERE timestamp >= date('now', '-90 days')
GROUP BY date(timestamp), action
ORDER BY day DESC;
```

## Key Technical Decisions

### 1. Customer Matching Strategy
**Decision:** Use CID from EMR as primary key
- EMR already has CID field in format `CID-{uuid}`
- Very reliable, no fuzzy matching needed for most cases
- Fuzzy matching only for edge cases (typos, missing CIDs)

### 2. Service Mapping Storage
**Decision:** Store in Supabase, editable via UI
- Start with seed data from COA_Quickbooks_matched.xlsx
- User can add/modify mappings as new services appear
- Version history not critical (current state is sufficient)

### 3. File Processing Approach
**Decision:** Upload → Stage → Review → Export
- All processing happens in backend
- Frontend is purely UI/review
- Keeps large files off browser memory
- Enables audit trail

### 4. Transaction Pro Format
**Decision:** Generate exact format from examples
- Your example files are the spec
- Validate output against actual imports
- Iterate based on Transaction Pro feedback
